## File Tools

### `list_dir`

List files and folders under a Godot project path (e.g., res://). Returns arrays of files and folders in the specified directory.

- `root` (string, required): Starting path like res://addons/ai_assistant or res://

### `read_file`

Read a text file from the Godot project, optionally a specific line range. Useful for reading GDScript files, scene files, or any text-based content.

- `path` (string, required): res:// path to the file (e.g., res://scripts/player.gd)
- `start_line` (number, optional): 1-based inclusive start line (optional)
- `end_line` (number, optional): Inclusive end line; 0 or missing means to end of file (optional)

### `search_project`

Search the Godot project for a substring and return file hits with line numbers. Useful for finding usages of functions, variables, or any text pattern.

- `query` (string, required): Case-insensitive substring to find
- `glob` (string, optional): Optional glob filter like **/*.gd to search only GDScript files

### `create_script`

Create a NEW GDScript file (.gd) that does not exist yet. Use this for creating new scripts, NOT for editing existing files (use edit_script for edits). Use classdb_query to verify unfamiliar Godot class methods. After creating a script, consider using run_scene to test and get_errors to check for issues.

- `path` (string, required): Script file path (res://scripts/player.gd) - must not exist yet
- `content` (string, required): Full GDScript content to write to the file

## Scene Tools

### `create_scene`

Create a new Godot scene (.tscn) file with nodes. Use this to create player scenes, UI screens, game objects, etc.

- `scene_path` (string, required): Scene file path (e.g., res://Scenes/player.tscn)
- `root_node_name` (string, optional): Name of root node (default: derived from filename)
- `root_node_type` (string, required): Type of root node (e.g., Node2D, CharacterBody2D, Control, Node3D). REQUIRED.
- `nodes` (array, optional): Array of child nodes to add. Each node spec: {name|node_name, type|node_type, properties?, script?, groups?, children?}. Use either {name, type} or the same {node_name, node_type} keys used at the top level — both work. Unknown keys (e.g. "class", "kind", "parent") return an error instead of silently producing a generic Node.
- `attach_script` (string, optional): Optional script path to attach to root node (res://path/to/script.gd)

### `read_scene`

Read and parse a scene file to get its full node structure and properties. Use this to understand a scene before editing.

- `scene_path` (string, required): Path to the scene file (res://path/to/scene.tscn)
- `include_properties` (boolean, optional): Include node properties in the output (default: false)

### `add_node`

Add a node to an existing scene file. Supports an optional script attachment, group memberships, and a tree of children created in the same call (1 tool call instead of N). Children format: {name|node_name, type|node_type, properties?, script?, groups?, children?}. Both key styles are accepted so children can reuse the same keys you use at the top level (node_name, node_type) or the shorter form (name, type). Unknown child keys are rejected with a clear error.

- `scene_path` (string, required): Path to the scene file (res://path/to/scene.tscn)
- `node_name` (string, required): Name for the new node
- `node_type` (string, required): Type of node (e.g., Sprite2D, Camera2D, RigidBody2D, CollisionShape2D)
- `parent_path` (string, optional): Path to parent node (. for root, or relative path like Sprite2D)
- `properties` (object, optional): Optional dictionary of properties to set on the node
- `script` (string, optional): Optional script path to attach to the new node (res://path/to/script.gd)
- `groups` (array, optional): Optional list of node groups this node should belong to. Persisted to the .tscn file.
- `children` (array, optional): Optional tree of children to create under the new node. Each entry has the same shape as add_node's args (minus parent_path). Use this to build sub-trees in one call.

### `remove_node`

### `modify_node_property`

DEPRECATED ALIAS of set_scene_node_property — identical behaviour, kept so existing callers keep working. Prefer set_scene_node_property. For multiple properties at once use set_node_properties. ALWAYS use a tool to modify .tscn files — NEVER edit them as text. To attach or change a script, use attach_script (NOT a property named "script") — this only rewrites the .tscn on disk, leaving the editor's in-memory node without the script, which makes connect_signal fail.

- `scene_path` (string, required): Path to the .tscn scene file
- `node_path` (string, optional): Path to the node (. for root, or relative path like "Sprite2D")
- `property_name` (string, required): Name of the property to modify (position, scale, rotation, modulate, visible, etc.)
- `value` (unknown, required): New value for the property. ANY JSON value accepted: primitives (numbers, strings, booleans, null), arrays, or objects. Use the {type, ...} discriminated form for Godot variant types. Common forms: numeric (e.g. 1.5), boolean (true), string ("hello"), Vector2 ({type:"Vector2",x,y}), Vector3 ({type:"Vector3",x,y,z}), Color ({type:"Color",r,g,b,a}), Quaternion ({type:"Quaternion",x,y,z,w}), Basis ({type:"Basis",euler:{x,y,z}}), Transform3D ({type:"Transform3D",basis:{...},origin:{x,y,z}}), AABB ({type:"AABB",position:{x,y,z},size:{x,y,z}}), Rect2 ({type:"Rect2",x,y,width,height}), NodePath (string starting with "."). For Resource-typed properties (Texture2D, Mesh, Material, Shape, etc.) DO NOT pass values here — use set_resource_property, set_sprite_texture, set_mesh, set_material, or set_collision_shape.

### `set_sprite_texture`

Assign a texture resource to a Sprite2D / Sprite3D / TextureRect node in a .tscn scene file. Modes:
  • FromPath  — load any texture file from disk (png/jpg/webp/svg/.tres) via load(). Returns whatever Texture2D the importer produced (usually CompressedTexture2D). Most common after generate_2d_asset.
  • ImageTexture (DEPRECATED ALIAS for FromPath, kept for back-compat)
  • NewImageTexture — force-create an ImageTexture (in-memory) from a raw image file.
  • PlaceholderTexture2D — in-scene placeholder of a given size.
  • GradientTexture2D / NoiseTexture2D — procedural textures.
Response always includes texture_class (the actual Godot class the texture decoded to), width, height, and texture_path so the agent can confirm what landed without an extra get_resource_info call.

- `scene_path` (string, required): Path to the .tscn scene file
- `node_path` (string, optional): Path to the Sprite2D/Sprite3D/TextureRect node
- `texture_type` (string, required): How to obtain the texture. Prefer FromPath for assets on disk.
- `texture_params` (object, optional): Texture parameters. FromPath / ImageTexture / NewImageTexture: {path: "res://assets/sprite.png"}. PlaceholderTexture2D: {size: {x: 64, y: 64}}. GradientTexture2D / NoiseTexture2D: {width, height}.

### `snap_node_to_ground`

- `ground_height` (number, optional): Ground plane height in world Y coordinates (default: 0)
- `use_bounds` (boolean, optional): Use the node subtree AABB bottom when available. If false, snap the node origin to ground_height instead (default: true)

### `place_node_relative`

Place one Node3D relative to another using bounds-aware world-axis relationships. Supports on_top_of, below, left_of, right_of, in_front_of, behind, and centered. Horizontal placement preserves the moved node elevation by default, and can optionally snap to a ground plane afterward.

- `scene_path` (string, required): Path to the .tscn scene file
- `node_path` (string, required): Path to the Node3D that should be moved
- `target_node_path` (string, required): Path to the anchor Node3D
- `relation` (string, optional): Placement relation: "on_top_of", "below", "left_of", "right_of", "in_front_of", "behind", or "centered"
- `gap` (number, optional): Optional spacing to leave between the moved node and the target (default: 0)
- `use_bounds` (boolean, optional): Use subtree bounds when available; otherwise fall back to node origins (default: true)
- `align_y_to_target` (boolean, optional): For left_of, right_of, in_front_of, and behind, vertically align to the target bounds center. Defaults to false so props keep their existing elevation.
- `snap_to_ground` (boolean, optional): After placing the node, move it vertically so its AABB bottom sits on ground_height (default: false)
- `ground_height` (number, optional): Ground plane height used when snap_to_ground is true (default: 0)

### `set_node_properties`

Set MULTIPLE properties on a node in a single tool call. Non-atomic: each property is applied independently; the response separates "applied" from "failed" so partial success surfaces clearly. Saves the scene once at the end. Resource-typed properties must use set_resource_property / set_sprite_texture / etc.

- `scene_path` (string, required): Path to the .tscn scene file
- `node_path` (string, optional): Path to the node (. for root, or relative path)
- `properties` (object, required): Map of property_name -> value. Each value follows the same form as modify_node_property.value (primitives, arrays, or {type:"Vector3",...} discriminated objects).

- `node_path` (string, optional): Path to the node (. for root)
- `groups` (array, required): List of group names to apply
- `mode` (string, optional): replace (default): node ends up in EXACTLY the listed groups. add: union with existing. remove: drop the listed groups.

### `set_resource_property`

Modify a property on a Resource that is currently held by a node (or by another resource attached to that node). Use this to tweak shape radii, material colors, gradient stops, etc., WITHOUT recreating the resource. resource_path walks from the node down to the resource using "/"-separated property names, e.g. "shape", "material", or "material/next_pass". After the change, saves the scene.

- `scene_path` (string, required): Path to the .tscn scene file
- `node_path` (string, optional): Path to the node owning the resource
- `resource_path` (string, required): Path from node to the target resource via property names. Examples: "shape", "material", "material/next_pass"
- `property_name` (string, required): Property on the target resource to set (e.g. "radius", "albedo_color")
- `value` (unknown, required): New value (same shape as modify_node_property.value)

### `save_resource_to_file`

Save a Resource currently held by a node (or sub-resource) to a standalone .tres file so it can be referenced by other scenes / shared / committed. The node's property is then re-pointed to the loaded-from-disk version, so future set_resource_property calls write through to that file. Works for any Resource subclass: Material, Mesh, Shape, Curve, Gradient, etc.

- `scene_path` (string, required)
- `node_path` (string, optional)
- `resource_path` (string, required): Path from node to the resource (e.g. "shape", "material")
- `save_to` (string, required): Destination path (res://.../foo.tres)

### `get_resource_info`

Inspect ANY Godot Resource. Two modes:
  • path mode: pass {path: "res://foo.png"} for a resource on disk (.tres / .res / image / .glb / .ogg / .tscn / etc.)
  • node mode: pass {scene_path, node_path, resource_property} to inspect a resource attached to a node WITHOUT having to save it as .tres first (e.g. the shape on a CollisionShape2D, the material on a MeshInstance3D, the stream on an AudioStreamPlayer).
Returns class, file size (path mode), and type-specific info: width/height for textures, vertex/surface counts and AABB for meshes, length for AudioStream/Animation, node count for PackedScene, common Material properties, Shape extents, and the resource's dependencies.

- `path` (string, optional): Path mode: resource path on disk (res://...).
- `scene_path` (string, optional): Node mode: path to the .tscn that owns the node.
- `node_path` (string, optional): Node mode: path to the node within the scene.
- `resource_property` (string, optional): Node mode: property name on the node holding the resource (e.g. "shape", "material", "stream", "texture").

### `list_signal_connections`

List signal connections involving a node. source="scene_file" (default) reads connections persisted to a .tscn. source="runtime" requires the game to be running and reads live connections from the SceneTree. Use the runtime mode to verify dynamically-connected signals (those connected from code in _ready, not in the editor).

- `source` (string, optional): Where to read connections from. Default: scene_file
- `scene_path` (string, optional): For source="scene_file": path to the .tscn
- `node_path` (string, required): Path to the node. For source="runtime" use absolute (/root/Main/Player) or relative to current_scene.
- `include_outgoing` (boolean, optional): Include signals that this node emits (default: true)
- `include_incoming` (boolean, optional): Include signals from other nodes whose handler is on this node (default: true). Only honored for scene_file source.

### `connect_signal`

Connect a signal between two nodes inside a .tscn scene file. The target script must define the method (will refuse otherwise). Equivalent to clicking the "+" in the editor's Node > Signals panel and persists the connection to the .tscn. NOTE: scripts must be attached via attach_script (NOT via modify_node_property), otherwise the editor's in-memory node will not see the script and this tool will reject the connection.

- `scene_path` (string, required)
- `from_node` (string, required): Path to the emitting node
- `signal` (string, required): Signal name on the emitting node
- `to_node` (string, required): Path to the receiving node
- `method` (string, required): Method name on the receiving node's script
- `flags` (number, optional): Connection flags (CONNECT_DEFERRED=1, CONNECT_PERSIST=2, CONNECT_ONE_SHOT=4). Default 0.

### `disconnect_signal`

Remove a signal connection from a .tscn scene file. No-op if the connection doesn't exist.

- `scene_path` (string, required)
- `from_node` (string, required)
- `signal` (string, required)
- `to_node` (string, required)
- `method` (string, required)

## Editor Scene Tools

### `call_node_method`

Invoke a method on a node in the currently open Godot editor scene tree. Use this for @tool workflows that need a live SceneTree context, such as baking terrain, regenerating scatter, rebuilding helper nodes, or running other editor-side scene mutations that cannot work on an orphaned PackedScene instance.

- `scene_path` (string, required): Path to the scene that must already be open in the Godot editor
- `node_path` (string, optional): Relative path to the target node inside the open editor scene. Use "." for the root node (default: ".")
- `method_name` (string, required): Method name to invoke on the target node
- `args` (array, optional): Optional argument list passed to the method. Values use the same structured Variant shapes as other scene tools.
- `save_scene_after` (boolean, optional): Save the currently open editor scene after the method call. Disable this if you want the scene to stay dirty for manual review (default: true)

## Editor View Tools

### `take_editor_viewport_screenshot`

Capture the current Godot editor 3D viewport to a PNG file. Use this for visual verification after scene edits or placement changes.

- `viewport_index` (number, optional): 3D editor viewport index from 0 to 3 (default: 0)
- `output_path` (string, optional): Optional res:// path, user:// path, or relative path (mapped to user://) for the PNG file. Defaults to user://mcp_screenshots/editor_viewport_<timestamp>.png. Absolute paths outside the project are rejected unless allow_absolute_output=true.

## Layout Tools

### `summarize_scene_layout`

Analyze a 3D scene using CollisionShape3D geometry and return a top-down layout summary with floors, walls, obstacles, scene bounds, and detected wall openings.

- `scene_path` (string, required): Path to the .tscn scene file
- `runtime` (boolean, optional): Inspect the currently open editor scene tree instead of loading the .tscn file from disk. This sees live editor-state overrides, but not the separate running game process.
- `floor_height_threshold` (number, optional): Maximum AABB height that should still count as floor geometry (default: 0.75)
- `wall_height_threshold` (number, optional): Minimum AABB height required for a shape to be considered wall-like (default: 1.5)
- `thin_threshold` (number, optional): Maximum wall thickness used to classify thin wall segments and broad floor surfaces (default: 1.0)
- `line_merge_tolerance` (number, optional): Tolerance used when grouping nearby wall segments onto the same line for opening detection (default: 0.25)
- `min_opening_width` (number, optional): Minimum wall gap width that should be reported as an opening (default: 0.75)

## Lighting Tools

### `get_light_info`

Inspect a 3D light in a scene file. Returns transform data, shadow settings, emitted direction, and directional-light diagnostics such as sun angles and scene-tree sky order.

- `scene_path` (string, required): Path to the .tscn scene file
- `node_path` (string, optional): Optional path to the Light3D node. If omitted, the first Light3D in the scene is used.
- `runtime` (boolean, optional): Inspect the currently open editor scene tree instead of loading the .tscn file from disk. This sees live editor-state overrides, but not the separate running game process.

### `set_sun_light`

Configure a DirectionalLight3D using sun-style azimuth/elevation angles instead of raw Euler rotation. This prevents the common error of lighting the scene from below. Also accepts optional shadow, color, and directional-shadow settings.

- `scene_path` (string, required): Path to the .tscn scene file
- `node_path` (string, optional): Optional path to the DirectionalLight3D node. If omitted, the first DirectionalLight3D in the scene is used.
- `elevation_degrees` (number, optional): Sun elevation above the horizon in degrees. Positive values place the sun above the horizon and point the light downward.
- `azimuth_degrees` (number, optional): Sun compass angle around +Y in degrees. 0 = sun in front of the scene along -Z, 90 = sun on +X.
- `allow_below_horizon` (boolean, optional): Allow negative sun elevation values. Defaults to false to guard against accidental under-lighting.
- `color` (object, optional): Optional light color, e.g. {type:"Color",r:1,g:0.95,b:0.9,a:1}
- `energy` (number, optional): Optional Light3D.light_energy value
- `indirect_energy` (number, optional): Optional Light3D.light_indirect_energy value
- `volumetric_fog_energy` (number, optional): Optional Light3D.light_volumetric_fog_energy value
- `specular` (number, optional): Optional Light3D.light_specular value
- `temperature_kelvin` (number, optional): Optional Light3D.light_temperature value
- `angular_distance` (number, optional): Optional Light3D.light_angular_distance value for sun disc size / softening
- `shadow_enabled` (boolean, optional): Enable or disable shadows
- `shadow_bias` (number, optional): Optional Light3D.shadow_bias value

### `take_screenshot`

Capture the current viewport of the running game and save it as a PNG. REQUIRES the game to be running with the MCPRuntime autoload connected (run_scene with wait_for_runtime=true first). ALWAYS saves to disk and returns the path, dimensions and byte size. Set return="image" to additionally receive the frame as an inline image the model can actually look at — that is the only form a vision model can perceive; base64 inside a text field is unreadable. IMPORTANT: prefer query_runtime_node / get_ui_controls for anything numeric or behavioural — a still frame cannot show whether collision, timing or performance is correct, and one angle can mislead. Default save location is res://addons/godot_mcp/cache/screenshots/.

- `save_to` (string, optional): Optional res:// or user:// destination path. Defaults to res://addons/godot_mcp/cache/screenshots/screenshot_<ms>.png

- `return_base64` (boolean, optional): Also include the raw base64 in the JSON body. Rarely needed — the server already converts it to a proper image block when return="image". Provided for clients that want the string itself.
- `max_dimension` (number, optional): Downscale so the longest edge is at most this many pixels (default: 1568, which is where vision models clamp anyway). Set 0 to disable downscaling.
- `max_bytes` (number, optional): Refuse to inline a PNG larger than this many bytes (default: 6291456 = 6 MiB). On overflow the file is still saved and the error reports its path.

### `runtime_eval`

Execute arbitrary GDScript inside the running game and return the serialized result. REQUIRES confirm=true as an explicit safety gate — omitting it returns an error. Also REQUIRES the game to be running with the MCPRuntime autoload connected (run_scene with wait_for_runtime=true first). The code runs in a temporary Node attached to the game tree, so it can touch any live node: get_tree().current_scene, $Player, await, etc. A trailing expression is returned automatically (e.g. "1 + 2" returns 3); for multi-line code or coroutine results use an explicit "return expr" or "return await ...". WARNING: this has full control over the running game (it can quit it, crash it, or corrupt state) — prefer safer tools like query_runtime_node / runtime_call_method when they suffice. Returns {result} with the value serialized (Vectors, Colors, Transforms, Arrays, and Dictionaries all supported).

- `code` (string, required): GDScript to evaluate in the running game. Examples: "get_tree().current_scene.name", "get_viewport().get_visible_rect().size", "var x = 5\nx * 3", "await get_tree().create_timer(1.0).timeout\nreturn 'done'".
- `confirm` (boolean, required): REQUIRED. Must be explicitly set to true — safety gate against silently executing arbitrary code in the running game.

### `runtime_wait`

Await N game frames in the running game so the engine actually ticks before the agent continues. Unlike the server-side "wait" tool (which only sleeps and does not advance the game), this suspends the tool call until the game has processed the requested frames. Use between send_input calls and before query_runtime_node / take_screenshot so physics and logic settle. Frame-rate dependent: at 60fps, 60 frames ≈ 1 second. Capped at 3000 frames.

- `frames` (number, optional): Number of frames to await (default: 1, max 3000).
- `frame_type` (string, optional): "render" (default) awaits process_frame; "physics" awaits physics_frame.

### `runtime_await_signal`

REQUIRES the MCPRuntime autoload connected.

- `node_path` (string, required): Absolute path (e.g. /root/Main/Player) or relative to current_scene.
- `signal_name` (string, required): Signal name to wait for (e.g. animation_finished, died, body_entered).
- `timeout` (number, optional): Seconds to wait before giving up (default 10, range 0.1..25).

### `runtime_call_method`

Call a method on a live node in the running game and return the serialized result. For editor-scene (not running) method calls, use call_node_method instead. Use for direct interactions the input tools cannot express: player.take_damage(10), game.start(), save_game(), etc. For coroutine/await-style methods or arbitrary code, use runtime_eval (which additionally requires confirm=true). REQUIRES the MCPRuntime autoload connected.

- `node_path` (string, required): Absolute path (e.g. /root/Main/Player) or relative to current_scene.
- `method_name` (string, required): Method name to call on the node.
- `args` (array, optional): Arguments to pass to the method (default []).

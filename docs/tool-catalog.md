## File Tools

### `list_dir`

List files and folders under a Godot project path (e.g., res://). Returns arrays of files and folders in the specified directory.

- `root` (string, required): Starting path like res://addons/ai_assistant or res://

### `read_file`

Read a text file from the Godot project, optionally a specific line range. Useful for reading GDScript files, scene files, or any text-based content.

- `path` (string, required): res:// path to the file (e.g., res://scripts/player.gd)
- `start_line` (number, optional): 1-based inclusive start line (optional)
- `end_line` (number, optional): Inclusive end line; 0 or missing means to end of file (optional)

### `search_project`

Search the Godot project for a substring and return file hits with line numbers. Useful for finding usages of functions, variables, or any text pattern.

- `query` (string, required): Case-insensitive substring to find
- `glob` (string, optional): Optional glob filter like **/*.gd to search only GDScript files

### `create_script`

Create a NEW GDScript file (.gd) that does not exist yet. Use this for creating new scripts, NOT for editing existing files (use edit_script for edits). Use classdb_query to verify unfamiliar Godot class methods. After creating a script, consider using run_scene to test and get_errors to check for issues.

- `path` (string, required): Script file path (res://scripts/player.gd) - must not exist yet
- `content` (string, required): Full GDScript content to write to the file

## Scene Tools

- `scene_path` (string, required): Scene file path (e.g., res://Scenes/player.tscn)
- `root_node_name` (string, optional): Name of root node (default: derived from filename)
- `root_node_type` (string, required): Type of root node (e.g., Node2D, CharacterBody2D, Control, Node3D). REQUIRED.
- `nodes` (array, optional): Array of child nodes to add. Each node: {name, type, properties, script, children}.
- `attach_script` (string, optional): Optional script path to attach to root node (res://path/to/script.gd)

### `instance_scene`

Add an instance of another scene (.tscn) as a child node. This is how you compose scenes from reusable parts (like prefabs). The instance maintains a live reference to the source scene. Use this instead of add_node when you want to reuse an existing scene.

- `scene_path` (string, required): Path to the scene file being edited (the parent scene)
- `instance_path` (string, required): Path to the .tscn scene to instance (the child/prefab scene)
- `node_name` (string, optional): Optional name for the instance. If omitted, uses the instanced scene's root node name.

### `set_sun_light`

- `elevation_degrees` (number, optional): Sun elevation above the horizon in degrees. Positive values place the sun above the horizon and point the light downward.
- `azimuth_degrees` (number, optional): Sun compass angle around +Y in degrees. 0 = sun in front of the scene along -Z, 90 = sun on +X.
- `allow_below_horizon` (boolean, optional): Allow negative sun elevation values. Defaults to false to guard against accidental under-lighting.
- `color` (object, optional): Optional light color, e.g. {type:"Color",r:1,g:0.95,b:0.9,a:1}
- `energy` (number, optional): Optional Light3D.light_energy value
- `indirect_energy` (number, optional): Optional Light3D.light_indirect_energy value
- `volumetric_fog_energy` (number, optional): Optional Light3D.light_volumetric_fog_energy value
- `specular` (number, optional): Optional Light3D.light_specular value
- `temperature_kelvin` (number, optional): Optional Light3D.light_temperature value
- `angular_distance` (number, optional): Optional Light3D.light_angular_distance value for sun disc size / softening
- `shadow_enabled` (boolean, optional): Enable or disable shadows
- `shadow_bias` (number, optional): Optional Light3D.shadow_bias value
- `shadow_normal_bias` (number, optional): Optional Light3D.shadow_normal_bias value
- `shadow_blur` (number, optional): Optional Light3D.shadow_blur value
- `light_cull_mask` (number, optional): Optional Light3D.light_cull_mask value
- `shadow_caster_mask` (number, optional): Optional Light3D.shadow_caster_mask value
- `editor_only` (boolean, optional): Optional Light3D.editor_only value
- `visible` (boolean, optional): Optional Node3D.visible value
- `sky_mode` (string | number, optional): Optional DirectionalLight3D.sky_mode. Use light_and_sky, light_only, sky_only, or a numeric enum value.
- `directional_shadow_mode` (string | number, optional): Optional DirectionalLight3D.directional_shadow_mode. Use orthogonal, parallel_2_splits, parallel_4_splits, or a numeric enum value.
- `directional_shadow_max_distance` (number, optional): Optional DirectionalLight3D.directional_shadow_max_distance value
- `directional_shadow_blend_splits` (boolean, optional): Optional DirectionalLight3D.directional_shadow_blend_splits value

Inspect the persisted signal connection graph of a saved Godot scene using scene-file metadata. This is the editor-facing source of truth for saved scene connections, not an inferred script graph. Returns source node paths, signal names, target node paths, methods, flags, binds, and optional validation against the instantiated editor scene.

- `scene_path` (string, required): Path to the .tscn scene file
- `include_inherited` (boolean, optional): Include connections declared in base scenes when inspecting an inherited scene (default: true)

### `update_scene_signal_connections`

Batch add or remove persisted signal connections in a saved scene file. Use this to edit saved scene-connection truth in the editor workflow; added connections are always persisted with CONNECT_PERSIST and the scene is saved once after the batch.

- `stop_on_error` (boolean, optional): Stop processing remaining operations after the first error (default: false)
- `operations` (array, required): List of add/remove operations to apply before a single scene save.

### `get_input_map`

Return the full InputMap: built-in actions (ui_*, spatial_editor/*) plus all project-defined actions from project.godot. Each action maps to an object with "events" (array of key/mouse/gamepad bindings) and optionally "deadzone". Use this before configure_input_map to see current bindings and deadzones.

- `include_deadzones` (boolean, optional): Include the per-action "deadzone" field in each action object (default: true). When true, each action is {"deadzone": 0.5, "events": [...]}. When false, each action is {"events": [...]}.

### `get_collision_layers`

Return named 2D/3D physics collision layers from ProjectSettings.

No input properties.

### `get_node_properties`

Get available properties for a Godot node type. Use this to discover what properties exist on a node type (e.g., anchors_preset for Control, position for Node2D).

- `node_type` (string, required): Node class name (e.g., "Sprite2D", "Control", "Label", "Button")

### `get_console_log`

Return the latest lines from the Godot editor output log.

- `max_lines` (number, optional): Maximum number of lines to include (default: 50)

### `get_errors`

Get errors and warnings from both the Godot Output panel and the Debugger > Errors tab. Returns file paths, line numbers, severity, stack traces, and which source each error came from. If errors mention a missing method or property, use classdb_query to verify the correct API before fixing.

- `max_errors` (number, optional): Maximum number of errors to return (default: 50)
- `include_warnings` (boolean, optional): Include warnings in addition to errors (default: true)

### `clear_console_log`

Mark the current position in the Godot editor log. Subsequent get_console_log and get_errors calls will only return output after this point.

No input properties.

### `open_in_godot`

Open a file in the Godot editor at a specific line (side-effect only).

- `path` (string, required): res:// path to open
- `line` (number, optional): 1-based line number

### `scene_tree_dump`

Dump the scene tree of the scene currently open in the Godot editor (node names, types, and attached scripts).

No input properties.

### `list_settings`

Browse Godot project settings by category. Returns values from the editor's in-memory state — this matches project.godot after a normal Godot save, but direct edits to project.godot on disk are not reflected until the editor restarts (rescan_filesystem does not help). Call without a category to see all available categories. Call with a category to see all settings with their current values, types, and valid options.

- `category` (string, optional): Settings category prefix (e.g., "display", "physics", "rendering", "application", "audio"). Omit to list all available categories.

### `update_project_settings`

Update one or more Godot project settings. Pass a dictionary of setting paths to their new values. Use list_settings first to discover available setting paths, current values, and valid options for a category. For input action bindings, prefer configure_input_map — if you do pass input/* keys here, partial updates are merged safely (existing events are preserved).

- `settings` (object, required): Dictionary of setting paths to new values (e.g., {"display/window/size/viewport_width": 1920, "display/window/size/viewport_height": 1080})

### `configure_input_map`

Add, remove, or replace input actions and their key/button bindings. Use get_input_map to see current actions before modifying.

- `action` (string, required): Input action name (e.g., "move_left", "jump", "attack")
- `operation` (string, required): "add" to create action and/or append events, "remove" to delete the action entirely, "set" to replace all events on an action (creates it if needed)
- `deadzone` (number, optional): Action deadzone (default: 0.5)
- `events` (array, optional): Input events to bind. Each object needs a "type" field: {"type":"key","key":"Space"} for keyboard, {"type":"mouse_button","button_index":1} for mouse (1=left,2=right,3=middle), {"type":"joypad_button","button_index":0} for gamepad, {"type":"joypad_motion","axis":0,"axis_value":1.0} for gamepad axis.

### `run_scene`

Run a scene in the Godot editor. Returns immediately — the scene launches asynchronously. Recommended workflow after editing code: 1) run_scene, 2) wait a few seconds (longer for large projects), 3) is_playing to confirm the scene started (if false, it crashed — check get_errors), 4) get_errors to check for runtime errors, 5) stop_scene before making fixes.

- `scene` (string, optional): Scene to run: omit for main scene, "current" for the open scene, or a res:// path for a specific scene

### `stop_scene`

Stop the currently running scene in the Godot editor. Always stop the scene before editing code to avoid errors repeating every frame.

No input properties.

### `is_playing`

Check if a scene is currently running in the Godot editor. Returns playing status and the scene path. Use after run_scene to confirm the scene started successfully — if playing is false shortly after run_scene, the scene likely crashed on startup.

No input properties.

### `classdb_query`

Query Godot's ClassDB for class information: properties, methods, signals, and inheritance. Use this to verify that a class, method, or property actually exists in the running Godot engine before writing code. Prevents using wrong method names, outdated Godot 3 API, or incorrect signatures.

- `class_name` (string, required): Godot class name to query (e.g., "CharacterBody2D", "Sprite2D", "Control")
- `query` (string, optional): What to return: "all" (default), "properties", "methods", or "signals"
- `include_virtual` (boolean, optional): Include well-known virtual methods like _ready, _process, _input (default: true). Set to false to see only public non-virtual methods.

### `rescan_filesystem`

Trigger a full filesystem rescan in the Godot editor. Use after creating, deleting, or modifying files externally (e.g. from the terminal or another tool). The scan is asynchronous and returns immediately.

No input properties.

### `setup_autoload`

Register, unregister, or list autoload singletons. Autoloads are scripts/scenes loaded automatically at project start.

- `name` (string, optional): Autoload name (e.g., "GameManager", "AudioManager")
- `operation` (string, required): "add" to register, "remove" to unregister, "list" to show all autoloads
- `path` (string, optional): res:// path to the script or scene file (required for "add")

## Asset Tools

### `generate_2d_asset`

Generate a 2D sprite/texture from SVG code and save as PNG. Use for custom visuals (characters, objects, backgrounds, UI). Returns resource_path and dimensions.

- `svg_code` (string, required): Complete SVG code string with <svg> tags including width/height.
- `filename` (string, required): Filename for the asset (saved as .png). Example: "player_sprite.png"
- `save_path` (string, optional): Godot resource path to save (default: res://assets/generated/)

## Visualizer Tools

### `map_project`

Crawl the entire Godot project and build an interactive script-level map of GDScript files showing their structure (variables, functions, declared signals) and inferred code relationships (extends, preloads, regex-parsed connect() usage). This is a source-code graph, not saved scene-connection truth. Opens an interactive browser-based visualization.

- `root` (string, optional): Root path to start crawling from (default: res://)
- `include_addons` (boolean, optional): Whether to include scripts in the addons/ folder (default: false)

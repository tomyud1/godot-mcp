# Godot MCP 0.6.0 — Undo, batching, and validate-before-mutate

The release that makes AI edits **reversible**. Every mutating tool now snapshots before it runs, so `mcp_undo` can roll back anything the agent did. `batch_execute` collapses multi-step workflows into one call — and one undo entry. Compound tools validate the whole request before touching disk, so a typo'd property name fails cleanly instead of half-applying.

**13 new tools** (63 → 75), **21 bug fixes**, **5 breaking changes**.

---

## Headline features

### 1. Undo/redo for AI changes

`mcp_undo`, `mcp_redo`, `mcp_undo_history`.

Every mutating tool snapshots the files it will touch into a disk-backed ring buffer at `res://addons/godot_mcp/cache/undo/` (200 entries / 100 MB, oldest evicted). Coverage is automatic — a registry in `tool_executor.gd` drives it, so scene mutations, script edits, file ops, and project settings are all included without per-tool code.

`mcp_undo_history` lists both stacks with tool name, args summary, files touched, and age, so the agent can decide how far back to go. Scenes and scripts open in the editor auto-reload on undo.

> **Ctrl+Z still doesn't reach AI changes.** The plugin works load→mutate→save on disk rather than through the editor's live tree, so there's no `EditorUndoRedoManager` action to revert. Ask the agent to undo instead.

Failed tools do **not** auto-rollback — partial mutations stay put so you can decide what to do. The snapshot is just discarded.

### 2. `batch_execute` — many calls, one transaction

An ordered list of tool calls in a single request. "Add a node, set 5 properties, attach a script, connect 2 signals" goes from 9 round trips to 1, and commits as **one undo entry**.

- `atomic: true` (default) — any failure rolls back every earlier success from snapshots. The batch fully applies or appears never to have happened.
- `atomic: false, stop_on_error: true` — stop at first failure, keep the partial result.
- `atomic: false, stop_on_error: false` — run everything, report every failure.

Disallowed inside a batch: nesting, the undo tools, `wait`, `run_scene`/`stop_scene`. Structurally pre-validated, so typos surface before any mutation. Guide at `godot-mcp://guide/batching`.

### 3. Validate before mutate

`add_node`, `create_scene`, and `set_node_properties` now check the **entire** spec before writing anything: every `node_type` against ClassDB, every `script` path exists *and* loads, every property key real on the target class (including `@export`s on the attached script), recursing through all descendants.

Failures return path-pointed errors — `children[2].properties.text: property does not exist on Sprite2D` — with **zero** mutation. No scene load, no file creation, no save. This catches the single most common agent failure: guessing `color` when the property is `modulate`.

### 4. `call_method` — drive the running game

Invoke any method on any node, in the editor's on-disk scene or the live game. The write counterpart to the read-only `query_runtime_node`. `Player.take_damage(50)`, `AnimationPlayer.play("intro")`, `Curve2D.add_point(pos)` — things `send_input` can't reach because they need structured arguments.

Editor mode saves the scene back and snapshots for undo. Runtime mode routes through the `MCPRuntime` autoload.

One subtlety worth knowing: Godot instantiates editor scenes with `GEN_EDIT_STATE_MAIN`, which attaches scripts but does **not** dispatch method bodies for non-`@tool` scripts. `callv("take_damage", [50])` would silently return null and the agent would reasonably conclude the method ran and returned void. Editor mode now detects this and refuses with `reason: "non_tool_script_method"` plus a pointer to runtime mode. Built-in C++ methods are unaffected.

Method typos return `closest_matches` (top-5 by string similarity) and arity is pre-checked against `MethodInfo`, so the agent self-corrects in one round trip. Destructive methods (`queue_free`, `free`, `set_script`, `remove_child`, `replace_by`, `reparent`) require `confirm: true`.

### 5. Folder and file writing

- **`delete_folder`** — recursive delete as a single undo entry. Three guards that refuse cleanly rather than half-delete: files open in the editor (`force: true`), external `res://` references (`force_orphan: true`), and contents over the undo cap (`allow_no_undo: true`). Refuses to touch `res://` root or the plugin's own directory. Non-empty folders need explicit `recursive: true`. Closes [#52](https://github.com/tomyud1/godot-mcp/issues/52).
- **`write_file`** — generic UTF-8 text writer. `create_script` was previously the only way to write a text file, so agents misused it for `.gdignore`, `.json`, `README.md`, `.gdshader`, custom `.tres`. Path-traversal guard, plugin-source guard, and editor cache sync after write. Overwrite gated behind `overwrite: true`.

### 6. Editor awareness

`get_editor_selection` / `set_editor_selection` read and write the Scene-dock selection, so "fix **this**" and "change the color **here**" work without typing a node path. Returned paths match `find_nodes` / `scene_tree_dump` format and pass straight into other tools. Guide at `godot-mcp://guide/selection-workflow` lists the trigger phrases.

## Other new tools

- **`find_nodes`** — general scene search, replacing `find_nodes_in_group`. ANDs `name_pattern` (auto-detects glob vs substring), `type` (matches subclasses and `class_name`), `in_group`, `recursive`. `scene_path` now optional, defaults to the active scene. Unknown types error instead of returning silent zero matches.
- **`get_performance_monitors`** — runtime `Performance` snapshot: fps, frame time, draw calls, static memory, orphan nodes, custom monitors. For post-`run_scene` verification and before/after optimization claims.
- **`get_scene_node_properties`** — the handler existed since 0.5.0 but was never published, so the agent couldn't discover it. Returns the *full* property list including `@export` vars, vs. `read_scene`'s curated subset. Use it to verify a write actually landed.
- **`close_editor_tabs`** — unified scene + script tab closer, for resetting the editor to a known state between test runs. Scenes close via `EditorInterface.close_scene()` (Godot 4.5+); Godot exposes no API to close script tabs, so those are reported in `scripts_closed_not_supported` rather than silently skipped.

## Bug fixes

**Crashes and silent data loss**

- `add_node` / `create_scene` **crashed** with `"Tool returned no status"` when `children` / `groups` / `properties` / `nodes` had the wrong type. GDScript 4 typed locals throw at assignment, before the validator runs. Locals are now Variant, so the validator reports it cleanly.
- `add_node` **silently dropped `@export` properties** — `set_script()` ran *after* properties were applied, so custom vars no-op'd against a script-less node and returned `ok: true`. Script now attaches first.
- `rename_file` **left broken references**. Now rewrites literal `res://` refs across `.tscn`, `.tres`, `.gd`, `.cs`, `.gdshader`, and `project.godot`, updates autoloads, moves `.uid` sidecars, and rebinds `ResourceUID`.
- `rename_file` **discarded unsaved scene edits** while refreshing tabs. Now guarded by Godot's dirty-state API; on versions without a reliable check (e.g. 4.6.2) reload is skipped with a warning instead of closing the tab.
- `rename_file` **corrupted undo snapshots** — the rewrite scan now skips the undo cache.
- `mcp_undo` of `create_folder` **left the directory on disk**. `KIND_CREATED` assumed file content, so `file_exists()` returned false for a directory and skipped removal. Records now carry `is_dir`. Backward-compatible with existing manifests.

**Diagnostics** (the [#49](https://github.com/tomyud1/godot-mcp/issues/49) cluster)

- `get_errors` now reads the **Debugger > Errors** tree, not just the Output panel — classifying warnings vs errors by row icon, extracting stack traces, and resolving bare `foo.gd:line` frames to full paths. The resolver prioritizes the most recently run scene, fixing wrong-file reports when two scripts share a basename.
- `get_errors` gained `wait_ms` (capped 1000ms). Debugger rows can land a few frames after the editor flips to playing, so an immediate post-`run_scene` check used to report a false "0 errors".
- `get_console_log` **detects Output panel filters**. With the Info filter off, `print()` lines are hidden before the tool can scrape them — the response now says so instead of returning an empty log.

**False negatives**

- `validate_script` reported `valid: false` for **perfectly valid scripts**. `can_instantiate()` returns false for free-floating GDScripts with no `resource_path` — typical of a just-saved file. Parse success now drives `valid`; `can_instantiate` is still reported for callers that need it.
- `validate_script` now explains `@tool`/addon parser-context failures (`error_code: 43`) instead of returning a bare dead end.

**Runtime and timing**

- `run_scene({wait_for_runtime: true})` **spuriously reported `runtime_connected: false`**. The poll loop used `OS.delay_msec()`, freezing the main thread and therefore `MCPClient._process()` — the only place WebSocket frames are read. The connect push sat unread until the loop ended. Now yields via `await create_timer().timeout`. (Same root cause fixed in `wait` last release.)
- `run_scene` is now a registered coroutine, required for the above to return a `Dictionary` rather than a `GDScriptFunctionState`.
- `run_scene.startup_timeout_ms` is clamped to 25000ms, 5s under the bridge's transport timeout, which used to eat the structured response. Non-fatal — the response reports the clamp.
- `rescan_filesystem` no longer hard-errors when a scan is already running. The in-flight scan covers it, so it returns `ok: true, already_scanning: true`.

**Type safety and transport**

- `set_node_properties` accepted `texture: 1` on fresh nodes — the old guard only fired when the property *already* held a Resource, missing the common case of a new Sprite2D with `texture` still null. Now reads the declared variant type from `property_list`.
- The generic error wrapper stopped injecting `mode: 'live'` into every failure, which collided semantically with `set_editor_selection`'s own `mode: "replace" | "add"`.
- Composite tools (`batch_execute`, the undo trio) now route through the success transport path. Their `ok: false` is a *semantic* result — "the batch had 2 failures" — not a transport error, and was getting wrapped in the generic MCP error envelope, losing the structured body.
- The TS bridge stopped stripping `ok` / `error` from merged failure details.
- `batch_execute` no longer commits empty undo entries for read-only batches.

## Quality of life

- **`scene_tree_dump` pagination** — `subtree_root`, `max_depth`, `offset`, `limit`. All optional, fully backward compatible. Adds `total_node_count`, plus `truncated` and `next_offset` when output was clipped.
- **`get_runtime_status` reports the Godot version** (`godot_version` + full `Engine.get_version_info()`), so bug reports bind to a build without asking the user to open the About dialog.
- **`get_editor_selection` emits a stable `reason`** — `ok`, `none_selected`, or `no_scene_open` — so agents branch on a field instead of string-matching `message`.
- **`set_editor_selection.node_paths` advertises `oneOf: [string, array]`.** A bare string always worked, but strict MCP clients could reject it before it hit the wire.
- **`edit_script` description** dropped the "SMALL, SURGICAL (1-10 lines)" framing that was steering models away from medium and large edits. It always supported full-file rewrites. Closes [#48](https://github.com/tomyud1/godot-mcp/issues/48).

## Upgrade notes

Five breaking changes:

1. **`set_node_properties` is atomic.** Any validation failure aborts the whole call with `ok: false`. The `failed` field is gone — `validation_errors` replaces it. Previously each property applied independently and the call returned `ok: true` even when some failed.
2. **Every tool returns a top-level `ok`.** It used to be stripped from successful responses, so callers inferred success from the absence of `error`. Code reading `error` is unaffected; code reading `result.ok` starts working correctly.
3. **`create_script` rejects non-`.gd` paths**, returning `wrong_extension: true` and pointing at `write_file`. Missing extensions still auto-complete to `.gd`. The docs always said GDScript-only; the implementation just didn't enforce it.
4. **`find_nodes_in_group` is removed.** Replace `find_nodes_in_group({scene_path, group})` with `find_nodes({scene_path, in_group: group})`. Same match shape, plus `groups` on every result.
5. **`close_scene_tabs` → `close_editor_tabs`**, no schema alias. It was never in a release, so this only affects anyone tracking `main`.

Also worth knowing:

- Versions bumped to 0.6.0 across `mcp-server/package.json`, `mcp-server/server.json`, and `addons/godot_mcp/plugin.cfg`.
- The undo cache lives at `res://addons/godot_mcp/cache/undo/`. It's plugin scratch space — add it to `.gitignore` if you don't want snapshots in version control.
- The README's "No undo" limitation is gone, replaced by the Ctrl+Z caveat above.

## Tests

52 automated tests passing. The tool-registry test was extended to recognize built-in tools dispatched through the `match tool_name:` block in `tool_executor.gd` — it had been silently failing to cover `mcp_undo` / `mcp_redo` / `mcp_undo_history` since the undo work landed, and `batch_execute` would have inherited the same gap.

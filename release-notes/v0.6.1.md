# Godot MCP 0.6.1 — No more silent no-ops

While building a level with the plugin, an agent reported a pattern: several tools answered `ok: true` and changed nothing. A texture path passed to `create_scene` was dropped. `call_method("set_texture", ...)` did nothing. `run_scene` ignored a misspelled argument and launched the wrong scene.

These weren't separate bugs. Each tool converted JSON to Godot values its own way, Godot's `Object.set()` silently ignores a value of the wrong type, and nothing checked tool arguments. So this release fixes the causes with three shared foundations instead of patching tools one by one. The tool list also gets **smaller (75 → 69)**, because six specialized tools are no longer needed. Every existing call keeps working.

---

## 1. One way to write properties, guided by type

Every tool that writes a property or passes a method argument now goes through one writer. It looks at what the property expects and reads the JSON accordingly:

```json
{
  "texture": "res://hero.png",
  "shape": { "type": "RectangleShape2D", "size": { "x": 32, "y": 16 } },
  "material": { "type": "CanvasItemMaterial" },
  "material:blend_mode": "Add",
  "texture_filter": "Nearest",
  "modulate": "#ffcc88"
}
```

- **Resources** take a file path or an inline resource whose keys are its own properties. The result must match the property's class: a PNG for a `mesh` is an error, not a no-op.
- **Colon paths** (`"shape:radius"`) edit a resource the node already holds.
- **A String property keeps `"res://..."` as text.** A blanket "load anything that looks like a path" would have broken script variables like `next_level = "res://level2.tscn"`; type-guided reading avoids that.
- **Every write is read back.** If Godot clamps or wraps a value, you get it in `adjusted`. If Godot ignores the write, it's an error.
- **Nothing is saved unless everything is accepted**, and every problem comes back at once with the exact property and a "did you mean".

Because a texture, shape, mesh or material is now just a property value, `set_sprite_texture`, `set_collision_shape`, `set_mesh`, `set_material`, `set_resource_property` and `modify_node_property` are hidden from the tool list. They still work (and now also through the same writer), and their responses point at the `set_node_properties` equivalent.

## 2. Tool definitions are enforced

The server now checks every call against the tool's declared arguments before anything reaches Godot:

```
Invalid arguments for run_scene: unknown argument 'scene_pth' (did you mean 'scene_path'?)
usage: run_scene({ scene_path?: string, block_until_started?: boolean, ... })
```

`batch_execute` sub-commands are checked the same way. Clients that send JSON as strings, numbers as strings, or `null` for optional arguments keep working.

Strict checking is only safe if the definitions match what the plugin really reads, so a new test compares the two for every tool. On its first run it found five arguments the plugin supported but no schema declared (`read_file.max_bytes`, `search_project.max_results`, ...). They would have become impossible to use.

## 3. Consistent names

Arguments holding a scene are `scene_path`, files are `path`, nodes are `*_node_path`: `run_scene.scene` → `scene_path`, `list_dir.root` → `path`, `connect_signal.from_node` → `from_node_path`, and `edit_script` takes flat `{path, old_text, new_text}`. Old names are still accepted.

The plugin keeps receiving the old names on the wire, so **any plugin version works with any server version**. That matters because `npx` always fetches the newest server while the plugin is updated by hand. The plugin now also reports its version, and `get_godot_status` warns when they differ.

## Also

- `query_runtime_node` with no `properties` returns the node's state: script variables plus everything that differs from its defaults (a Label's text, a body's velocity).
- `send_input` rejects unknown keys, actions and fields instead of sending nothing.
- `set_node_properties` can edit a `.tres` directly (`scene_path: "res://mat.tres"`).
- A headless plugin test suite runs against real Godot, in game mode and inside the editor.

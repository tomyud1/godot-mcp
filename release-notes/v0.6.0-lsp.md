# Godot MCP — LSP-powered script validation & code intelligence

This release replaces the entire `validate_script` backend with **Godot's built-in Language Server Protocol (LSP)** server, and adds four new code-intelligence tools. Together these give AI agents the same structured diagnostics and navigation capabilities that human developers get from the Godot script editor.

## Why replace `validate_script`?

The old implementation had three fundamental problems:

1. **Isolated parsing** — `GDScript.new()` + `reload()` has zero project context. It doesn't know about autoloads, class hierarchies, or cross-file references. Any script that extends another class would be flagged as "cannot be instantiated."

2. **Screen-scraping errors** — to get human-readable error messages, the code walked the editor's internal UI node tree (`EditorLog` → `RichTextLabel`) and parsed BBCode text with regex. This broke if Godot's UI changed, and frequently picked up stale errors from previous edits.

3. **No line/column precision** — the best the old approach could do was "there's an error somewhere in this file." LSP diagnostics include exact line, column, severity, and error codes.

The LSP server, in contrast, parses every script with full project-wide context. It understands class inheritance, autoload singletons, signal connections, and type inference — exactly what the script editor's own error panel shows.

## New tools

| Tool | What it does |
|------|-------------|
| `validate_script` | Returns structured diagnostics (line, column, severity, error code, message) |
| `goto_definition` | Jumps to where a symbol is defined (class, function, variable, etc.) |
| `find_references` | Finds every usage of a symbol across the project |
| `get_symbol_info` | Retrieves type annotations, documentation, and function signatures |
| `list_document_symbols` | Lists all symbols in a file as a hierarchical tree |

## Architecture

```
                    ┌─── WebSocket (6505) ──── Godot Editor Plugin
                    │    (all other tools)
MCP Server (TS) ───┤
                    ├─── TCP LSP (6005/6065) ─── Godot LSP Server
                    │    (validate_script, goto_definition,
                    │     find_references, get_symbol_info,
                    │     list_document_symbols)
                    │
                    └─── HTTP (6506) ─── Proxy clients
```

The five LSP tools bypass the Godot plugin entirely. The TypeScript MCP server opens a direct TCP connection to Godot's LSP server (default port 6005) and communicates via standard LSP protocol (JSON-RPC 2.0 over TCP with `Content-Length` framing).

## Configuration

```json
{
  "mcpServers": {
    "godot": {
      "env": {
        "GODOT_MCP_LSP_PORT": "6065"
      }
    }
  }
}
```

- `GODOT_MCP_LSP_PORT` — defaults to `6005`. Set this to match Godot's `network/language_server/remote_port` if you've changed it.
- Godot's LSP must be enabled: `Editor Settings → Network → Language Server → Enable`.

## Robustness

The LSP connection layer was stress-tested through multiple Godot editor restart cycles. It handles:

- **Godot LSP startup race** — the LSP server's TCP port may accept connections before the LSP handshake is fully initialized. The MCP server retries up to 8 times with exponential backoff (200→320→512→… ms, capped at 5 s).

- **Godot editor restart** — when the editor restarts, the old LSP socket is released (via targeted `socket.off()` cleanup, not `removeAllListeners()`), and a fresh connection is established with the full retry loop.

- **Windows URI encoding** — Godot LSP on Windows percent-encodes `D:` as `D%3A` in diagnostic URIs. The client decodes these transparently.

- **Diagnostic settle windows** — Godot LSP may publish diagnostics in multiple rounds (an empty batch during initial parse, then real errors). The client waits with a 300 ms minimum + 200 ms quiet window to avoid returning empty results.

- **Unhandled rejection safety net** — `vscode-jsonrpc` may produce asynchronous promise rejections for pending requests on a dead socket during reconnect. A `process.on('unhandledRejection')` handler catches these at the process level so the MCP server never crashes on transient socket errors.

## Backward compatibility

- `validate_script` has the same `{path}` input schema — no agent changes needed.
- The old `GDScript.reload()` code has been removed from `script_tools.gd` (~70 lines of code).
- `get_godot_status` now includes `lsp_port` and `lsp_connected` fields.
